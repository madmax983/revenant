# Install Readiness

The **Readiness** panel is the first panel on the System Doctor tab of the Workflow Dashboard. It tells you if the install is correct. Each `Warn` and `Fail` names the missing item and the fix.

The panel runs when System Doctor opens, on **Refresh Status**, and on **Run Checks**. It shows the round-trip time (target: less than 2 s).

## Notes

- The panel runs each time System Doctor loads its status (open, **Refresh Status**, **Enqueue Watchdog**, pause and resume), and on **Run Checks**. It shows the round-trip time. The target is less than 2 s.
- The access checks use the user that opens the dashboard. The engine writes in system mode. Only custom Apex, Flow, or integrations that create these records in user mode need create access. A read-only operator (`Revenant_Operator`) gets `Warn`, not `Fail`.
- The package ships no `Default` alert config. A new install gives `Warn` for Failure alerts until you make one.
- A new install has no watchdog until the first workflow start or a click on **Enqueue Watchdog**.
- The watchdog check reads the liveness state only. It does not run the stall detector, so it sends no alert. A running chain with no sweep yet (`UNKNOWN`) passes.
- The access checks read all package fields of each object from describe (no formula, no auto number). A field of another package is not checked. In a namespaced install, a subscriber field is not checked. Without a namespace, a field that you add to these objects is checked too.
- A check that cannot run gives `Warn` with the error. The other checks still run.
- The panel only reads. It makes no DML, starts no job, publishes no event, and changes no schema. It uses `getInstance`, describe calls, and two bounded SOQL queries (`ApexTrigger`, the latest watchdog instances). The view gate adds one query when the user passes it through Modify All Data.
- Endpoint: `WorkflowReadinessController.getReadinessChecks()`. Both `Revenant_Operator` and `Revenant_Admin` grant it. It uses the dashboard view gate.
